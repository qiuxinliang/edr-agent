# Agent 3.2.499 UTM 验证与定点修复

## 结论与范围

2026-09-15 对 UTM 的 WIN-FAC3AC1PS5O 执行实际验证。以下时间除明确注明外均为 UTC。
结论是**部分链路验证成功，但不能宣布端到端数据完整性通过**。

- 确认运行的是官方 3.2.499 ARM64 二进制，不是旧安装残留。
- 长命令行在本地保留超过原来讨论的 288 字节，并保留测试尾标记。
- 受控脚本文件写入同时在本地与服务端找到，进程身份一致。
- 同一脚本文件的两条 FileRead 在本地有路径，却缺进程代际；定位到规则兴趣提前返回跳过身份关联，完成源码修复。
- 受控网络连接在本地找到准确进程身份，但本次未建立服务端对应记录的闭环。
- 自动取证仍频繁下发，并出现真实自动隔离；停止新增案例，未绕过安全策略。

本轮没有替换 UTM 二进制、修改采集策略、停用自动隔离或手工修改隔离状态数据库。
这里只提交窄范围 Agent 修复；服务端重复补证与 Worker 部署问题单独列为未解决事项。

## 3. 实证根因与修复

旧路径：

`FileRead 已有路径 → 不命中规则兴趣 → 写入证据缓存并 return → 跳过进程身份关联`

同一进程的 ProcessCreate 和文件写入已有准确 StartKey/creation，但这条提前返回路径没有复用它们。
这是检测兴趣与证据保留身份关联耦合的问题，不是需要无条件扩大字段或提高全量采集比例。

修改：在该提前返回分支，尽力复用**既有、事件时间匹配的历史进程代际**后再保留事件。

- 复用原有 cached-generation 算法，将其放入内部共享头文件以直接测试实际代码。
- 不增加 OS 查询、采集源、线程、配置、外部依赖或运行时组件。
- 不把非规则命中的读取升级为 P0，不添加新的失败门禁。
- cache miss、代际冲突或路径截断时不猜测身份，保留原有安全边界。
- 命令行原有截断来源仍明确传播，不伪造用户名或读取时 token。
- 网络无源代际且仅有开放 PID 生命周期的拒绝条件保持不变。

这个修复覆盖的是**路径已知、历史进程已采集、却被提前返回漏关联**的读取。
它不解决 ETW 路径解析缺失，也不承诺补齐所有服务端事件。

## 5. 自动补证与隔离：独立的服务端风险

固定窗口 10:55:33.068–11:25:33.068：对该终端下发 **50 条 collect_forensic 命令**。
抽查最近命令关联 `pb-auto-evidence-demo-tena-40f9e71e`，
决策 action=`agent.forensic_memory`、mode=`auto`，部分已 succeeded。
不能据此宣称全部命令均由本次测试直接触发，需要按告警来源进一步归因。

源码已有 `trustGateAutomaticEvidenceBudget`（端点级 10 分钟自动补证预算），
但实际命令仍频繁产生。这不是通过继续编译 Agent 可以解决的问题。

部署证据：

- 预算修复所在服务端提交 `3bfcb3c9`：2026-09-15 18:18:13 +0800。
- API 当前 PID 34408，OS 启动时间 19:26:35 +0800，运行状态表 role=api。
- Worker PID 70875，OS 启动时间 2026-09-14 22:36:34 +0800；运行状态表仍持续心跳，
  role=worker，groups 包括 pipeline/response/context 等。
- API 更换以后仍存在新自动取证命令；仅更新 API 不代表 Worker 已更新。

这构成 **Worker 未随补证修复同步部署的强疑点**，但本轮没有读取其内存构建指纹，
因此不将源码提交时间当作已证明的二进制版本。
后续应先确认 Worker 运行版本、通过其启动 owner 更新，再以实际命令窗口验证预算效果。
本轮未重启其他正在工作的服务，未关闭自动策略，未修改服务端数据。

隔离命令 `cmd_isolate_1789470485219354000` 有 execution_status=1、exit_code=0 回执，
接收时间约 11:08:57Z；11:21:32 终端隔离防火墙规则为 7 条。
因此当前隔离不是单纯 UI 显示错误。发现后停止新增案例。
用户已授权单次解除并核验，但浏览器连接两次超时，尚未提交解除命令；已请求用户在运维页面手动提交。
不能把获得授权或命令提交视为解除完成，需另核验命令回执、规则清除和服务端状态。
