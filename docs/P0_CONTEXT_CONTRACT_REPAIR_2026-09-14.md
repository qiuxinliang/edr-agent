# P0 context contract repair — 2026-09-14

## 本轮边界

修正已验证的上下文传播与截断问题，不改规则签名、TLS、终端处置授权、
离线耐久队列、自动隔离策略或产品版本。服务端配套提交：`b3143790`。
本轮没有部署 Agent 或重启服务，不能把代码回归通过解释成现场完整率已提升。

## 删除或合并的冗余条件

- ProcessCreate、文件和网络 actor 复用上下文补全入口，不再因事件类别被排除。
- 已有用户名不再阻止采集缺失的完整性级别和令牌权限；仍从同一个已验证进程句柄取得 token。
- 已验证的轻量进程信息在 4688 合并等待之前发布给缓存；去掉重复的早期进程树写入。
- 服务端进程上下文关联不再强制要求成功取得文件身份；进程代际仍要求 PID、StartKey、创建 FILETIME 和规范路径。
- 过期的代码文本形状断言由对应行为用例覆盖；没有删除 4688 不具生命周期权威的断言或行为约束。

## 完整性与来源修复

- 进程树的 cmdline/path 从 256/512 字节对齐到现有 BehaviorRecord 的 4096 字节字段容量（包含终止符）。
- 常见短字段内联，长值按实际长度分配；截断和分配失败通过字段级 provenance 传播。
- 本地证据缓存对齐相关字段容量，并保持 parent/grandparent 的代际证明。
- 父进程创建时间保留小数秒，避免秒级格式化破坏 FILETIME 精确关联。
- 文件证据失败原因区分 UTF-8 转换、打开、身份查询、文件信息查询、目录和重解析拒绝，并保留 Win32 错误码。
- 网络 actor 绑定失败时保留 IP/端口及候选落盘，不借回旧 PID 的进程、权限、hash、父链或 PMFE 历史。
- 服务端禁止未来权限回填、A/缺失/B 文件身份冲突穿透，以及跨事件 hash/signature/artifact 权威传播；nearby 也使用同样约束。

## 保留的上限和成本

没有无限放大所有字段，也没有取消证据写入配额、磁盘容量、排队或超时上限。
现有字段合同之外的内容必须显式标记截断，不能声称完整。
关键/普通上下文默认 160/40 次写入每分钟保持不变，调整需要单独的负载与耐久性验证。

缓存结构测算（64 位）：

- 进程树固定表约增加 96 KiB；长字段全部占满时，按需分配理论额外上限约 32 MiB。
- ProcessTreeEntry 快照从 944 增至 8376 字节。
- 1024 个 ProcSlot 固定空间约增加 10.164 MiB。
- 缓存实现与相关测试的 AppleClang 262144 字节栈帧检查无超限；这不是 Windows 全调用链栈验证。
