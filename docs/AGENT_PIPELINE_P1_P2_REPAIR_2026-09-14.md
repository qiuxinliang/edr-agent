# Agent 流程 P1 / P2 修复

## 范围

对应流程简化评审中的数据保留、投影、进程代际、慢 I/O、传输所有权和停机问题。
仅修改 Agent；不修改生产策略，不部署安装包，不操作 UTM 或终端隔离。
优先保持安全、数据完整性和恢复能力，而不是单纯减少代码行数。

## 按链路落实的修改

| 原问题 | 修改后契约 | 主要验证 |
| --- | --- | --- |
| 上传去重会提前结束本地证据保留 | 本地证据先接收记录；上传选择、去重不再决定是否交给证据所有者 | `telemetry_admission`，缓存重放回归 |
| JSON 仍有 220 / 360 / 260 字节的隐式字段截断 | 总投影能容纳时保留完整字段；总容量不足时整字段省略，带来源和原因；原始记录不变 | 长路径、命令行、注册表、UTF-8、最坏容量、分配失败 |
| PMFE 仅按 PID 关联结果 | Windows 使用实际扫描句柄取得 PID + StartKey + creation FILETIME；不同代际不可借用扫描摘要 | PID 复用、晚到结果、缺少代际、重置 |
| 预处理串行等待可选哈希/签名 | 有界异步续处理保留原始记录，其他已就绪记录不被慢任务阻塞 | 后到先就绪、超时、满槽、退出取消、完整原始字段 |
| 预处理线程同步进行网络队列排空 | 复用传输线程执行 SQLite 队列发送；预处理只进行本地耐久交接 | 阻塞发送期间仍可完成本地交接 |
| 内存发送、可选落盘、失败再落盘有多个所有者 | 一个 SQLite 耐久交接点；交接失败时聚合器保留已封存批次；发送及 ACK 沿用现有队列实现 | 失败保留、稳定 batch ID、RAW/LZ4 字节一致、退避、关停重试 |
| 同一上下文按候选告警反复序列化和消耗预算 | 一份不可变上下文事实，多条候选关联；变化事务计一个上下文工作单位；完全重放计零 | 多候选扇出、重放、升级、事务失败、容量清理 |
| Windows 等待线程退出的结果被忽略 | 只有确认退出并完成批次交接才释放依赖；失败保留资源并报告失败 | 关停超时、禁止错误重启、再次完成关停 |
| 多线程同时追加、刷批、改配置或释放批次 | 同一互斥所有者保护完整批次状态；关停后新追加明确失败，不访问已释放内存 | 四生产者 + 配置/刷批并发、4,000 唯一事件、并发关停交接计数 |
| AVE 队列未排空就退出，采集器超时仍继续销毁 | 采集器退出失败阻止后续销毁；预处理退出后排空 AVE，再释放批次；超时保留状态 | 阻塞回调 + 20 个排队事件、超时后重试、停止接收、重复关停 |
| 进程合并槽可能在期限前被关停重置 | 显式停机排空；Security-only 仍为补充证据；不伪造关联、不重复输出墓碑记录 | 未到期排空、只含 Security、已输出记录不重复 |
| 已通过 Windows 策略的同一记录再次判断 | AVE 接收前复用既有上传判定结果，不重复执行同一策略 | 预处理集成契约与运行时检测回归 |
| 未使用的拆分发送路径、无效压缩级别配置 | 删除无支持调用者的拆分/注入路径及无效 LZ4 级别开关 | 调用者检索、产品构建、压缩批次测试 |
| `send_ok` 在 HTTP 完成前增加 | 分开统计尝试、成功和失败；成功只在底层调用成功后增加 | 真实返回码注入，成功/失败计数断言 |

## 保留的边界及理由

- `detection_context` 的 4 KiB 是现有记录/传输投影边界，不再被当作完整证据存储。
  `omitted_fields`、`omission_sources`、`projection_limited`、`invalid_fields`
  和 `evidence_complete=false` 说明投影损失；不能把省略当成源端没有采集。
- 异步证据续处理最多 32 项，与证据工作者的现有槽位上限一致，按需分配。
  保留原有 1 秒观察窗口。满槽或超时只降低可选证据完整度，不删除源事件，不伪造哈希或签名。
- 上下文预算继续区分关键上下文和普通上下文，默认 160 / 40 个工作单位每分钟。
  不再因一个源事件关联 20 个候选就扣除 20 份载荷预算。
  保留磁盘容量、保留期限和关联窗口界限；P0 候选既有预算豁免不变。
- 批次交接失败后有退避。连续到达的新事件不能绕过退避并反复写失败的 SQLite。
  聚合器未交接的内存数据不具备进程崩溃耐久性，不能虚称已保存到队列。
- 保留 TLS/mTLS、命令签名与防重放、P0 规则权威性、进程代际校验、队列 ACK、
  损坏检测、重试、回滚和诊断。不以跳过失败测试换取通过。

## 运行组件和兼容性

新增的运行时状态只有预处理续处理槽和证据库的事实/关联存储；没有新增线程、服务或第三方依赖。

证据库用 `context_facts` 保存内容寻址、不可变的上下文载荷，
`candidate_context_refs` 保存候选关联。
`materialized_artifacts` 提供带候选 ID 的完整工件投影；直接读取 SQLite 的工具应使用该视图，
不能继续把 `artifacts` 基础表当作所有上下文的全集。
历史载荷及关联在事务内迁移，坏数据导致明确失败并保留原始行，不以空结果替代成功。
迁移使用既有 SQLite JSON 处理保持大于 `2^53` 的整数精度，不经浮点反序列化/重写；
写入关联前核对已有事实的身份与载荷，避免损坏事实替代原始数据。
不同历史载荷版本不相互覆盖。
历史 `artifacts` 行保留供旧二进制读取，视图避免重复显示；重新升级时只导入较新的旧格式写入，
不会用保留的旧载荷覆盖新补全。新增的规范化上下文在降级期间仍保存在数据库中，
但只读取旧基础表的二进制看不到这些新事件，重新升级后恢复可见；本次没有执行生产降级。

RAM 发送队列被移除后，保留当前服务端仍读取的旧指标字段，其值为零；
实际积压应读取既有 `offline_queue_pending`。
新增 `batch_queue_owner=sqlite`、`batch_admission_failed`、`send_attempts`、
`context_facts_written` 和 `context_refs_written` 用于区分所有权、失败和物理工作量。

新增 `AVE_DrainBehaviorMonitor` 是现有预处理/销毁路径使用的有界停机接口，
不增加后台线程。自动刷批遵守退避；显式刷批/关停允许调用者控制的一次交接尝试。

Linux PMFE 扫描固定 `/proc/<pid>` 并校验扫描前后进程出生标识；
不把 Linux start ticks 冒充 Windows StartKey/FILETIME。
缺少可兼容代际时不填充历史 PMFE 摘要，独立扫描结果仍保留。

## 验证口径

本地构建为显式非生产 PCRE2 stub 配置，不能证明生产签名规则匹配链路已经通过。
跨平台编译不能替代 Windows MSVC 原生编译、原生运行或 UTM 实机数据回放。
不据此宣称新版本已上线。

执行结果：

- 本地 `edr_agent` 及 `agent_runtime_gate_tests` 构建成功；运行时标签测试 **30/30** 通过。
- `preprocess_p0_dispatch_contract` **1/1** 通过。
- `test_windows_release_gate.py` **17/17** 通过，包含 CMake 依赖图和平台分支探针；不是 Windows 原生运行证明。
- ASan/UBSan 定向验证：传输所有权、传输计数、续处理、上传准入、PMFE 代际、
  RAW/LZ4 批次、进程合并停机排空、上下文投影、证据库、AVE 排空，共 **10 项**通过。
- 批次并发测试额外通过 ThreadSanitizer；4,000 条事件无丢失或重复，
  并发关停时所有返回成功的追加都有唯一交接；RAW/LZ4 测试均完成 Windows 双架构交叉链接。
- Windows amd64/arm64 的相关翻译单元交叉编译；四个新增测试目标均完成两种架构的交叉链接，
  没有在 Windows 运行这些交叉生成的可执行文件。
- 20 候选 × 4 上下文的合成回归：新增 **4 facts / 80 refs / 4 预算单位**；
  注入事务提交失败时新增事实与关联均为零，恢复后一次完整提交。
- 600 字节文件路径在总投影未超限时完整保留；长 UTF-8、控制字符、最坏容量和分配失败路径均有回归。
- Shell 模板语法和 `git diff --check` 通过。

这些是代码及合成回归数据，不是此前 220 条现场告警或 UTM 新版本部署的实测结果。

生效的弱符号空实现掩盖了测试依赖缺口；单源文件交叉编译也不能发现链接错误。

  `test_ave_sdk` / `test_ave_pipeline` 链接成功。两个 AVE 测试及其 ASan/UBSan 运行均为 2/2 通过。
- 两个完整 CMake 测试目标完成 Windows amd64（MinGW）和 arm64（Zig/Clang）交叉链接，
  共生成四个 EXE，而不只是编译修改文件。交叉配置未启用 SQLite/OpenSSL/Curl，
  属于链接依赖检查，不代表生产配置或 Windows/MSVC 原生执行已通过；本地运行测试使用真实 SQLite。
