# ADR：Shellcode 检测与 TLS 边界（T-SC-050）

## 状态

**已采纳**（与当前代码一致）：**不在 `proto_parse.c` 内解析 TLS 记录层**；TLS 载荷在 WinDivert 路径上视为 **raw/未知协议**，仅整体启发式（若启用）可能触发，**不做** 明文 HTTP/SMB 式子区间提取。

## 上下文

- 端上 **WinDivert** 所见多为 **加密** 445/443 等流量；**SMB2/HTTP 明文**解析仅覆盖 **未加密** 子集。  
- **完整解密** 依赖内核驱动、网关 MITM、或镜像 SPAN + 解密设备，属于 **跨模块** 与合规范畴。

## 决策

| 方案 | 说明 |
|------|------|
| **A. 仅端上** | 维持 **`proto_parse`** 仅处理明文；TLS 由产品文档标注为 **gap**。 |
| **B. 网关 / 解密镜像** | 由网络/平台团队交付 **明文副本** 或 **metadata**（JA3、SNI、五元组）至另一管道，**不**合并进本模块 TLS 解析。 |
| **C. 组合** | 端上保留 A；平台侧用 B 做关联告警。 |

## 后果

- **漏报**：纯 TLS 内 exploit 载荷不在当前 **已知规则 + 协议解析** 覆盖内。  
- **误报**：若未来引入半解密启发式，需单独 **FP/性能** 评审与 **T-SC-013** 类回归。
