# Bounded preprocessing stop diagnostic

`test_preprocess_stop_boundary` measures the current real preprocessing loop,
P0 emitter, IR loader and SQLite owners. The native comparison workflow builds
this opt-in target explicitly; it is not part of ALL or the release CTest count.
Production sources and shipped binaries are unchanged by this fixture.

The generator wraps calls once, retaining evaluation order and return values,
and verifies that removing the probes reproduces both original sources exactly.
The target reuses the runtime test objects, replacing only pipeline, P0 emitter
and the original policy owner with its existing deny-action test hook.

On Windows, one parent launches two fresh, Job-owned child processes, once each:
canonical authenticated IR ready, then genuinely missing IR. Together they have
85 seconds of work plus five seconds of terminal cleanup, a sampled cumulative
256 MiB fixture file-length guard and a combined 1 MiB worker-log guard. These
are sampled limits, not an OS disk quota. Unknown exit, forced termination,
missing completion receipts or failed cleanup fail the diagnostic. The Windows
evidence worker must also report zero shutdown timeouts, terminal-unhealthy
state and remaining slots; a void stop returning alone is insufficient. Artifacts
contain fixed numeric logs, hashes and source closure, never SQLite or rules.

Each child offers 16 synthetic process/network/file slots for its own live
process generation, sets the stop flag, and directly enters the real worker
loop. Windows child identities and observation times differ across variants;
compare their normalized input shape, not equality of raw input hashes.
The test separately reports a cold process-evidence request and seed creation,
then resets counters before measuring the loop. Stage timings are inclusive:
never add parent and child totals. The parent callback has no direct wrapper;
zero calls at stage 29 do not establish that it was not executed.

The fixture verifies one pre-existing necessary source owner's frozen bytes.
It does not verify every new input's durable disposition, SCM behavior, the
public start/join path, a running Agent, collectors, AVE, transport, or crash
recovery. Passing it is diagnostic evidence, not Service rollback acceptance.
No external action or network transport is initialized. Remove these probes
when the slow boundary is resolved and its focused regression owns coverage.

The comparison workflow also has a manual `diagnose_service_stop` input, false
by default. Only its ARM64 job runs this second diagnosis. It builds
`test_service_stop_agent` explicitly from the production Agent source list and
compile/link properties, replacing exactly the pipeline and local evidence cache
translation units with reversible numeric frontiers generated by `generate_service_source.py`.
This is an unshipped diagnostic executable with the real main, SCM, collectors
and durable owners. It is not a candidate package or a rollback acceptance test.

Its generated 60-second worker join observes the registered preprocess worker
at a nominal 10 ms cadence, using an absolute monotonic 60-second deadline and at
most 6001 samples. It adds no thread or event logging. A single bounded numeric
version-3 line contains 13 phase buckets and 135 callsite buckets, including
unknown zero. Two raw-byte source proofs bind the unchanged pipeline IDs 1..79,
cache envelope 80, and 44 direct cache calls 81..124. IDs 125, 126 and 127
are nested function envelopes for `sqlite_prepare_context_artifacts`,
`sqlite_size_budget_allow` and `sqlite_record_context_artifacts`, respectively.
They restore their caller ID after every normal return, including error returns,
and retain the original SQLite conditional-compilation scope. These envelopes
cover all calls on the registered worker, including callers such as
`record_alert_context`, rather than only site 114. One frontier identifies the
innermost wrapped helper, not its complete caller stack; nested populations must
not be added together or attributed exclusively to site 114.
Only the generated cache copy renames the public void body to a private
implementation and adds a thin ABI-preserving wrapper, so NULL, early return
and goto-done paths all restore the caller frontier. Its bridge uses the
pipeline's existing atomics and worker-thread gate, with no second cache state.
Only the registered worker publishes callsite frontiers. Cache calls from other threads publish
nothing. Exact int and uint32_t wrappers preserve return values; pointer,
int64_t and enum results remain within envelope 80. Site 54 also covers the
admission code after the cache call, including should_emit; only active cache
work switches to 80 or an inner site. Unwrapped callees inherit their caller ID,
and phase/callsite loads are independent. Counts are sample populations, not
exact durations, an atomic stack, or additive nested call timings. A capped
histogram is explicit. Observer overhead and low-power/suspension equivalence
to the original single wait are not validated. A signal first observed when
the observer resumes at or after its deadline remains a timeout; this can
conservatively reject a timely worker exit after observer scheduling delay.
It does not measure the worker's exact exit time. The selected consumer accepts only the version-2/128 or version-3/135 callsite tuple with 13 phase buckets, and checks each bucket and both sums; duplicate histogram lines fail instead of expanding
metadata. The original 45-second SCM verdict cannot be promoted by these samples.

Version 3 adds only 27 wrapped existing expressions within the context
transaction: 128 BEGIN IMMEDIATE; 129 retained-owner SQL (11 expressions);
130 fact SQL (10); 131 writer statement preparation; 132 reference puts;
133 writer finalization (two paths); 134 COMMIT, which may include SQLite
WAL auto-checkpoint work. Each literal has its own saved frontier. Error,
rollback, clock and other unwrapped gaps still inherit 127. These categories
are not complete block durations or individual SQL/fsync timing. Existing
IDs 1..127, SQL, transaction boundaries, synchronous/checkpoint settings,
sample cadence, sample cap and stop budgets remain unchanged.

45-second stop (45,171ms); later natural exit 1 and successful cleanup do not

3,275 of 3,782 samples fell within context transaction 127 (86.594%). Natural
ETW cohorts differ, so this is no equal-input A/B. The controlled host compact

public unbound Agent inputs and a fresh test-local temporary root. It starts
no Agent and performs no SCM mutation. The diagnostic preflight worker remains
bounded to 20 seconds. Its all-service enumeration uses the existing QA owner
pattern without a separate one-second CIM operation timeout; the process query
and later Snapshot query parameters remain unchanged. This single-variable
experiment follows an observed generic MI failure at operation 1, not proof
that the one-second parameter caused it. The same Core7 source previously
succeeded and failed; a successful experiment cannot establish that cause.
Service enumeration requests only
Name and PathName, the two fields consumed by the existing alias/path guard;
all services and the same guard remain covered. This reduces requested fields
and makes no claim that it resolves the historical stop or provider timeout.
Exit zero is accepted only with
the exact success schema, original three safety conditions, operation 5 and

The firewall precondition still reads effective `ActiveStore` profiles. In the
same child and shared 20-second budget it explicitly imports `NetSecurity` with
`ErrorAction Stop`, then runs the original profile query. A source-owned pure
validator requires exactly three unique names, `Domain`, `Private` and `Public`,
and each `Enabled` value's representation strictly `True`. Empty, duplicate,
missing, unknown or disabled profiles fail; local COM policy is not a substitute
for effective policy. Pure fixtures invoke this actual validator without
importing a module, querying a provider or modifying firewall state.
A failure reports fixed types, numeric positions and a closed stage/cause;
exception text is excluded. Unknown child identity, terminal state or stream
EOF fails cleanup and retains the public directory instead of claiming success.
The earlier WinPS5.1 eight- and twenty-second preflight failures remain failures;

control workers use the already-required Core7 executable, without a fallback

System32 WinPS5.1 owner. Changing the query host is not proof of a provider or
Service rollback fix. The temporary
20-second preflight budget is for observing the local provider/host response,
not a change to the 45-second Service stop verdict. The 270-second experiment
budget checks and existing remaining-budget gates before Service creation

The intent file records declared inputs before preparation, not verified facts.
The preparation test also reproduces an extra explicit public-fixture ACE left

Only SYSTEM and Administrators receive explicit inheritable FullControl;

PowerShell worker failures use the strict eight-field
`edr.ci-owned-failure.v2` schema. Operation IDs are 0 (not entered), 1 (service
query), 2 (process query and alias guard), 3 (machine environment presence),
4 (firewall query) and 5 (done); the private diagnostic adds 6 (before explicit
NetSecurity import) and 7 (import returned). Original 1..5 meanings are unchanged.
The actual order is 1,2,3,6,7,4,5, not a monotone progress counter. Up to eight
real exception nodes are inspected.
For real `CimException` nodes, `cim_native_error` preserves an Int32 getter or
the Int32-backed MI `NativeErrorCode` enum value; `cim_status_code` accepts only
the actual UInt32 `StatusCode` getter. Missing, other-type or throwing getters
remain null. They are separate from the outer exception's HResult. No error
message, ErrorData, arbitrary ID or stack is exported. Python stage failures
retain their strict v1 five-field schema; the unified v2 consumer projection
leaves its operation/CIM fields null. Extra, duplicate and mistyped fields are
rejected. Pure contracts use a real MI exception and only load the generated
projection function definition, without running a worker body or its exit.
These checks distinguish provider/host failures; they do not establish the
historical failure's CIM status, timeout cause or Service rollback acceptance.

The preflight also publishes one binary operation byte in its own fresh case.
The parent creates exactly one byte initialized to zero; before each operation
1..7 the worker overwrites that byte without growing the file. This is a private
diagnostic file write, not a system-state modification. The same bounded query
and 20-second preflight worker limits remain in force. The parent reads the
fixed file
only after confirming this invocation's held preflight process is terminal; the
early contract projects it after its exact-child cleanup. Only `status` and
`last_operation_id` are exported. Zero means no child progress was observed,
and says nothing about body entry; bad length/value, missing data or unknown terminal
state yields unknown/null. This last published operation is not a stack, elapsed
time, proof that a query is still running, or a timeout cause. Parent post-terminal
projection does not replace an earlier failure or promote its result. Checkpoint
I/O can itself fail before a query or consume time within the unchanged limits; a nonzero byte proves
publication only, not entry into or blockage in that query. Pure contracts load only
the byte-writer definition from the real preflight source, overwrite an existing
public one-byte fixture through operations 1..7, and verify that invalid values
or lengths fail without changing or expanding it. No preflight query or worker
body runs in that pure test.
The entire 20-second window includes service/process/environment operations as
well as module import and the profile query. A last-published 4 does not establish
that the query used all 20 seconds; 6/7 only separate import boundaries and do
not prove that cold module loading caused a historical timeout. No prewarming,
fallback, retry, new output field or increased limit is introduced.

The SCM harness requires a clean hosted runner and unique paths/service name.
It stages and verifies the complete static/delay-import DLL closure beside the
executable, rejects machine EDR overrides, blocks this exact program's outbound
traffic, and uses a closed loopback endpoint. No installer, updater, endpoint,
model request or real cache is involved. The preserved 692/701 template supplies
512 MiB queue and cache budgets and 8192 event slots. The original two-second
synthetic seed entry is reused; newly collected ETW input is not a replay of the
historical failure. Policy actions are alert-only and automatic forensics is off.

The harness freezes the original 45-second stop result before a separate
maximum 60-second observation. Its cooperative work limit is 240 seconds with
30 seconds for cleanup. File lengths are sampled against 256 MiB, live Agent
logs against 1 MiB, and free volume space against a 256 MiB floor. These are not
atomic disk quotas or measurements of allocated/physical device bytes.
Command-state, collector and temporary paths may be outside this sampled tree;
their existing owner budgets and free-space checks are not a global I/O quota.
SCM processes are not descendants of the harness Job: a held PID/birth/executable
identity is checked and cleaned separately. Forced cleanup cannot turn an
unsuccessful stop into a pass.

Substages 0..8 mean unknown, decode, generation, token, cache, evidence, P0,
correlation and record. Only a timeout emits their independent before/after
loads. They are neither an atomic stack nor per-call timing; P0 still contains
storage work and zero includes unwrapped gaps. The QA log reader accepts only
the versioned numeric vocabulary under its existing limits. Source manifests
prove each owner's raw-byte reversal, including CRLF input. Lock acquisition
includes the production lock-timing helper; metric/failure recording can flush
SQLite; candidate budget checks can run maintenance. Context artifact probes
include preparation, reads and budget checks as well as any transaction; exact
replay may not write. The three nested envelopes distinguish preparation reads,
capacity admission (which may maintain the cache), and the context transaction;
they do not measure individual SQL statements or fsync. These boundaries locate
the next owner, not a SQLite root cause or SQL duration.

### Diagnostic cache positive proof (private consumer candidate)

The generated diagnostic Agent emits one fixed `worker cache proof` JSON frame
from the still-registered preprocessing worker's normal exit tail. The consumer
only observes it after the original held target process has a known natural
terminal state, after firewall/control-worker cleanup and before closing the
original held log context. It uses only the remaining original cleanup deadline;
insufficient time yields an unknown proof. It adds an AND
condition to diagnostic acceptance. It does not rewrite `stop-result-frozen.json`,
45-second status, primary failure, or cleanup receipts. A late positive frame
cannot promote a failed stop. No frame is invented when observation is unavailable.

`PipelineSourceSha256` and `CacheSourceSha256` are mandatory raw-source SHA-256
arguments. The existing workflow can pass its `Pin` of the exact checkout files
`src/preprocess/preprocess_pipeline.c` and `src/storage/local_evidence_cache.c`.
Use the actual LF/CRLF bytes, matching the generator and transform manifests;
Git commit SHA is not a substitute. Both values are recorded in intent. The
preparation contract's isolated public prefix uses explicit dummy zero hashes;
it does not claim those inputs identify a compiled Agent.

The reader retains the original log stream/FileID, configuration hash, initial
EOF offset and anchor, and the exact held PID/birth/EXE-bound process object. It
uses the existing low-level guards, then reads the initial bound offset through
one stable EOF snapshot once. This is a separate consumer, not another call to
`ReadStopLogSlice` after that owner's final tail has sealed. Original offsets,
pending data, hash state and stream position are preserved. A one-attempt flag
is added. Before payload I/O, the fixed window length is reserved once in the
original `Context.readAttemptBytes` and diagnostic `read_attempt_bytes` ledger.
The proof `read_attempt_bytes` is that reservation; `bytes_read` separately counts
successfully returned bytes. A failed Read retains its charge and is not retried.
Short reads continue within the one reserved window. The original prior charge
plus this reservation must stay within the same 65536-byte allowance. Existing
config/anchor guard reads retain their separate original bounds. There is no second allowance,
retry, tail enlargement or added wait. Synchronous file operations are cooperative
with the original cleanup deadline; this is not an interruptible I/O quota.

Only one complete exact-prefix frame is accepted. The parser rejects duplicate,
missing, unknown or malformed keys, incomplete frame lines, wrong numeric types,
overflow, mismatched PID, path hash or source hashes. It exports only the closed
15-field frame plus finite read/provenance metadata and fixed causes. The
independently computed expected path digest is exported as
`expected_cache_path_sha256`, enabling the artifact reader to compare it again
with the validated frame without path text. No raw log,
path, base64, exception message, command, or unrelated line is exported. It keeps
the existing 4096-byte line and 128KiB metadata-file bounds.

A structurally valid format0 frame is observed but not positive, with
`compact_not_enabled`; positive requires format1 or2, db_open1, valid expected
path hash, retention clock valid, and nonzero committed context-fact/reference
counters. Candidate count may be zero. Those process-local counters include
candidate parent facts/references; they do not prove a new candidate, a completed
post-context drain, a reopen/crash durability check, or per-thread attribution.
The file/ACL and held-target binding does not supply cryptographic per-line
writer attribution. They exclude the false inference that Running or a faster
stop alone proves a healthy cache. Already-format2 performance is not inferred from format0 activation.

cache/clock/counters, missing/duplicate/partial frames, shared-cap boundaries,
