# Bounded preprocessing stop diagnostic

`test_preprocess_stop_boundary` measures the current real preprocessing loop,
P0 emitter, IR loader and SQLite owners. The native comparison workflow builds
this opt-in target explicitly; it is not part of ALL or the release CTest count.
Production sources and shipped binaries are unchanged by this fixture.

The generator wraps calls once, retaining evaluation order and return values,
and verifies that removing the probes reproduces both original sources exactly.
The target reuses the runtime test objects, replacing only pipeline, P0 emitter
and the original policy owner with its existing deny-action test hook.

On Windows, one parent launches two fresh, Job-owned child processes, once each:
canonical authenticated IR ready, then genuinely missing IR. Together they have
85 seconds of work plus five seconds of terminal cleanup, a sampled cumulative
256 MiB fixture file-length guard and a combined 1 MiB worker-log guard. These
are sampled limits, not an OS disk quota. Unknown exit, forced termination,
missing completion receipts or failed cleanup fail the diagnostic. The Windows
evidence worker must also report zero shutdown timeouts, terminal-unhealthy
state and remaining slots; a void stop returning alone is insufficient. Artifacts
contain fixed numeric logs, hashes and source closure, never SQLite or rules.

Each child offers 16 synthetic process/network/file slots for its own live
process generation, sets the stop flag, and directly enters the real worker
loop. Windows child identities and observation times differ across variants;
compare their normalized input shape, not equality of raw input hashes.
The test separately reports a cold process-evidence request and seed creation,
then resets counters before measuring the loop. Stage timings are inclusive:
never add parent and child totals. The parent callback has no direct wrapper;
zero calls at stage 29 do not establish that it was not executed.

The fixture verifies one pre-existing necessary source owner's frozen bytes.
It does not verify every new input's durable disposition, SCM behavior, the
public start/join path, a running Agent, collectors, AVE, transport, or crash
recovery. Passing it is diagnostic evidence, not Service rollback acceptance.
No external action or network transport is initialized. Remove these probes
when the slow boundary is resolved and its focused regression owns coverage.

The comparison workflow also has a manual `diagnose_service_stop` input, false
by default. Only its ARM64 job runs this second diagnosis. It builds
`test_service_stop_agent` explicitly from the production Agent source list and
compile/link properties, replacing exactly one pipeline translation unit with
the reversible numeric frontier generated by `generate_service_source.py`.
This is an unshipped diagnostic executable with the real main, SCM, collectors
and durable owners. It is not a candidate package or a rollback acceptance test.

The SCM harness requires a clean hosted runner and unique paths/service name.
It stages and verifies the complete static/delay-import DLL closure beside the
executable, rejects machine EDR overrides, blocks this exact program's outbound
traffic, and uses a closed loopback endpoint. No installer, updater, endpoint,
model request or real cache is involved. The preserved 692/701 template supplies
512 MiB queue and cache budgets and 8192 event slots. The original two-second
synthetic seed entry is reused; newly collected ETW input is not a replay of the
historical failure. Policy actions are alert-only and automatic forensics is off.

The harness freezes the original 45-second stop result before a separate
maximum 60-second observation. Its cooperative work limit is 240 seconds with
30 seconds for cleanup. File lengths are sampled against 256 MiB, live Agent
logs against 1 MiB, and free volume space against a 256 MiB floor. These are not
atomic disk quotas or measurements of allocated/physical device bytes. SCM
processes are not descendants of the harness Job: a held PID/birth/executable
identity is checked and cleaned separately. Forced cleanup cannot turn an
unsuccessful stop into a pass.

Substages 0..8 mean unknown, decode, generation, token, cache, evidence, P0,
correlation and record. Only a timeout emits their independent before/after
loads. They are neither an atomic stack nor per-call timing; P0 still contains
storage work and zero includes unwrapped gaps. The QA log reader accepts only
the versioned numeric vocabulary under its existing limits. Source manifests
prove raw-byte reversal, including CRLF input. Remove this diagnostic target,
manual workflow path and generator after a focused regression owns the fix.

`collect_service_diagnostic.py` exports only six named metadata JSON files.
Agent logs, databases, event bodies, full commands and the runtime directory
are excluded. Its offline tests use metadata fixtures and make no native or
Service execution claim. The earlier passed-tools artifact continues to attest
only its original native gates, even if the later Service diagnosis fails.
